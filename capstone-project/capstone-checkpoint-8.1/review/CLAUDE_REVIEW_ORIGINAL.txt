2. Strongest evidence-based objection
The experiment demonstrates safety properties but not net utility improvement, from a single unreplicated run. Baseline answered 5/6 correctly; guarded cold also 5/6 (it fixed A3 but lost B0). On this evidence the guarded system is slower (+34% latency, +62% tokens cold), costlier, and no more accurate on legitimate questions — its value rests entirely on the A3 resistance and the fail-closed guarantee, each demonstrated with a sample size of one. Furthermore, the live A3 comparison changes prompt, output format, and validation simultaneously, so it cannot attribute the resistance to any single safeguard (the self-checks prove the validator would reject a fabricated ID, but in the live run the model never attempted the fake citation — the prompt layer acted first). There is no retrieval precision/recall measurement, no independent groundedness scoring, no repeated-run variance, and answer-correctness judgments are assistant-reviewed rather than independently graded. The packet acknowledges all of this, which is to its credit — but a skeptical grader can fairly say: one attack, one run, no accuracy gain shown.

5. Ten challenging oral-defense questions (with accurate short answers)
“Your guarded system got the same score as the baseline — 5/6. Why is it better?”
The score hides asymmetric failure modes. Baseline’s miss was confidently citing a fabricated source (A3); guarded’s miss was withholding a correct-topic answer (B0). In production, a fabrication reaches the user; a fail-closed refusal is visible and recoverable. The trade is deliberate and measured: +34% latency, +62% tokens, fabrication eliminated in the tested case.
“Which safeguard actually stopped the A3 attack? Can you prove it?”
The live run can’t isolate one layer — prompt rules, structured format, and validation changed together. In the live guarded A3, the model never attempted the fake citation, so the prompt layer acted first. The offline self-checks prove independently that the validator alone rejects any citation ID not in the retrieved registry, so even if the prompt layer failed, the fabricated source could not be rendered. Isolation ablation is listed future work.
“Isn’t B0 a retrieval failure?”
No — both arms retrieved the identical five page records, including the two correct papers. The failure is in exact-quote validation: the model normalized PDF extraction artifacts (missing spaces like with>90%accuracy, hyphenated line breaks, ligatures), so its quotes aren’t byte-substrings of the extracted text. Whitespace normalization can’t bridge missing spaces or ligatures.
“Why not just loosen the quote matcher?”
Loosening it (fuzzy matching, edit distance) reopens the door to paraphrase drift — exactly what the validator exists to prevent. The better fix, listed as future work, is upstream: normalize extraction artifacts (de-hyphenation, ligature folding) in both the stored page text and the quote check, so matching stays exact over a cleaner canonical form.
“Your cache made the repeat workload slower. Why ship it?”
The pair was slower only because B0’s refusal is intentionally not cached — caching refusals would freeze transient failures. For the case the cache is designed for (exact repeat of a validated answer), A0 went from ~5.5 s and multiple paid calls to 0.0082 s and zero calls, with sources revalidated on every hit. The benefit is conditional and reported as such; no dollar-savings or hit-rate claim is made.
“How do you know your parser works — the facilitator asked exactly this?”
Partially. Preparation records 6,059 pages extracted with an ≥80-character page filter and a hash-pinned manifest, and B0 gave direct evidence of artifact classes the parser produces. What’s missing — and acknowledged — is sampled extraction-fidelity measurement against the source PDFs. That’s the top item on the evaluation-gap list, directly answering the Lab 8.2 feedback.
“What do your 19 offline checks actually test?”
Software behavior, not answer quality: validator rejections (fabricated IDs, bad quotes, .pdf in prose), input guards, cache TTL/FIFO/namespace isolation/invalidation, the repair path, and fail-closed behavior — all with a fake recorder, zero API calls. They are regression tests for the safety mechanisms, and the slides describe them that way.
“One run, one attack, assistant-reviewed answers. Why should I trust any of it?”
You shouldn’t trust it as a benchmark — and the packet doesn’t claim one. Every raw call, tool record, config, and hash is preserved for independent re-review; the limitations list explicitly disclaims attack-success rates, accuracy grades, and generality. The claim is narrower: in this recorded run, these specific behaviors occurred, and the safety properties are additionally code-enforced and unit-checked.
“Why BM25 instead of embeddings/vector search, which the course taught?”
BM25 was the Module 2 baseline and was retained deliberately: it’s deterministic, dependency-light, inspectable, and sufficient for this corpus’s keyword-heavy technical queries — retrieval was correct even in the failing B0 case. Semantic retrieval is future work; the packet doesn’t claim BM25 beat embeddings, only that it wasn’t the bottleneck here.
“If a question repeats but a PDF in the corpus changed, does the cache serve a stale answer?”
No. Cache keys include the corpus manifest digest, policy version, implementation SHA, model, and package set; any change produces a different namespace and a miss. Additionally, every hit deterministically revalidates its cited sources against the current registry before serving. TTL is 900 s and refusals are never stored.
