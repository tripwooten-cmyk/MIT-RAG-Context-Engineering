SLIDE 4: The Solution: workflow (1:05–2:00)

Follow the question through the diagram. Preparation extracts PDF pages and builds a BM25 keyword index. Ordinary code checks input length and control characters. Next comes an exact-question cache lookup. A matching entry must pass evidence revalidation against the loaded document snapshot before returning. If there is no valid entry, the model planner can search, open a page from a known paper, or answer. Each search returns up to three pages. The planner has four actions and can collect up to twelve pages. It then drafts a structured answer. Think of the planner as a coordinator and the index as the document locator. The dark boxes use the model, and the light boxes use code. This final path uses keyword retrieval. It does not use a vector database or hybrid search.

SLIDE 5: The Solution: validation (2:00–2:45)

The draft contains claims, source identifiers, and quotations. Code verifies that each source was retrieved and that its quotation occurs on the cited page after whitespace normalization. The application then supplies the filename and physical page number. A failed draft gets one repair attempt. A second failure withholds the answer, and refusals do not enter the cache. Accepted answers can remain for fifteen minutes, with a maximum of sixty-four entries. This resembles checking a submittal against its reference. The check establishes source occurrence. Human review still has to determine whether the passage supports the claim and whether the answer is complete.

SLIDE 10: Engineering Decisions (6:10–7:15)

These are deliberate choices with limits. First, I retained BM25 and the existing bounded agent to preserve the retrieval baseline while adding guards and caching. That gives an inspectable starting point. It does not prove BM25 beats vector or hybrid retrieval. A fair comparison would hold the corpus and test questions constant. Second, retrieved identifiers and exact quotations let code check source occurrence without another model judge. A judge might assess meaning more flexibly, but would add calls and its own errors. My strict approach exposed a real usability cost when B0 failed quotation matching. Third, the exact-question cache avoids semantic-match ambiguity and a model call on a valid hit. Lab 7.2 had shown that model-based cache validation could add substantial delay. Exact matching gives up reuse for paraphrases. I selected these choices for this controlled experiment, and the recorded workload shows exactly where they help and where they do not.
