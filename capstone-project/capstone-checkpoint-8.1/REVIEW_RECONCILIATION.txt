Corrections to the second review
Cache freshness: its last oral answer says a changed PDF cannot cause a stale hit. That is too strong. ExactCache captures context and revalidates against loaded document text. Disk changes require corpus reload and a refreshed fingerprint/context. A namespace is not user authorization, and a time limit is not proof of freshness.
A0 timing: the review's oral answer gives approximately 5.5 seconds before caching. Actual baseline A0 was 4.396399 seconds, guarded-cold A0 was 3.525653 seconds, and the valid exact repeat was 0.008214 seconds.
A3 attribution: the guarded answer did not attempt a fabricated citation, and it recorded zero validation rejections. That observation does not isolate the prompt as the causal protection. Prompts, context/answer format and validation changed together. The live result belongs to the guarded system as a whole.
Cost: use measured tokens and time. Avoid describing unverified billed-dollar differences as established costs.
Retrieval: identical B0 baseline/guarded-cold page IDs, including key supporting pages, diagnose that specific failure. They do not prove every page was relevant or that BM25 is sufficient across all corpus queries. The warm-B0 page set differs.
Quote matching: validation compares substrings after whitespace normalization, not raw byte substrings. Missing spaces, ligatures, hyphenation and case changes can still prevent matching.
Cache trade-off: B0's uncached execution explains where the repeated-pair time went, but the single run cannot attribute all timing differences solely to refusal caching. Provider/model variability remains a factor.
Source records: hashes establish identity for comparison, not immutability or truth of the contents. Git history and file hashes make changes traceable when properly maintained.
Slide references: several slide numbers and folder aliases in the second review do not match the delivered deck. SLIDE_EVIDENCE.csv provides the actual slide numbers and repository paths.
Guard scope: fabricated source-ID checks are enforceable within this code path. They do not prove general security or that every accepted claim follows from its quotation. Do not turn the defined fail-closed behavior into a universal safety guarantee.
